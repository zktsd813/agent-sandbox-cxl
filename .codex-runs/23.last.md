## 구조와 줄 수

상위 EPT 표는 CXL이다. 최하위 PT는 데이터 위치를 따른다. 모든 데이터의 CXL 집 주소는 그대로다.
기존 mapper fd의 로컬 overlay를 써서 VMM 주소·memslot을 유지했다.
계층 bit·누적 bitmap·DRAM 사본·PT는 로컬 상태다. 정상 packet에는 넣지 않는다.
전환은 정지·장치 drain 뒤에만 한다. Export는 전부 내리고 상위 표를 검사한다. 실패하면 재개하지 않는다.
16 MiB append-only 한도가 반복 왕복을 막아, 변환 비움·RCU 뒤 도달 불가능한 표만 로컬 bitmap에서 재사용했다.

22 HEAD 대비 추가 줄: KVM 195, mapper 94, Firecracker 164, 유지 시험 230이다.
KVM·mapper 합계는 289줄이다. 원시 실행·분석 스크립트 241줄은 별도다. 문맥·생성물은 뺐다.
새 daemon·공유 KVM 객체·공유 tier 장부는 없다. L0 정답지 영수증은 시험 모드만 사용한다.

## 정확성

- 2 GiB VM의 DRAM 0·1·16·512 chunk 조건에서 각각 200·100·100·100왕복 통과.
- 마지막 오류 차단 보완 뒤 lazy 100왕복, eager 100왕복+준비 1왕복, 절반 4이동 추가 통과. KVM과 데이터·PT 알고리즘은 동일하다.
- 정답지 켠 공유 EPT 정확성 이동 합계 1,447회. 누락 page 0, release/adopt 전체 16 MiB hash 1,447/1,447 일치.
- 절반 조건: DRAM 변경 13,112,470 page 관찰, 내림 13,634,279 page 관찰. 독립 tier hash 307,200검사 통과. EPT 최고 700,416 byte.
- Gin 원본 27명령 독립 검증. 이전 실행의 dirty 기록으로 315·175·175 chunk를 골라 명령 전에 올리고 대기 경계에서 내렸다. DRAM 구간 장치 bitmap 57,355 page 관찰.
- DRAM 잔류 release 거절, 복사 page 1개 누락, 다음 record page 1개 누락을 검출했다. HTTP export 오류는 source 종료로, 직접 내리기 오류 뒤 Resume는 HTTP 400으로 차단했다.
- 마지막 명시 TLB 비움 생략은 guest 오류가 없었다. Mapper notifier가 이미 비웠다. 모든 비움 경로를 생략한 시험은 아니다.
- 기존 race·HTTP·cache 정리 해제·빈 EPT·네 가지 오류 주입 통과. 빈 EPT는 준비 후 payload fault 65,536회씩이었다.
- Python 36개·Rust 고유 계약 14개 통과. 원본 patch fuzz·offset 0 적용 확인. 소유 lab·메모리 backing 정리 확인.

## 비용

모두 bud05 node 0의 중첩·DRAM 기반 CXL 에뮬레이션이다. 정답지 gate를 끈 ABAB 40 lab, 측정 920이동이다.
외부 Firecracker·QEMU 0개, 1분 load 0.56~1.14, node 0 free 18,818~19,755 MiB였다.

## Lab의 한계와 다음 실제 장비 시험

하드웨어는 L1 EPT가 아닌 L0 shadow 표를 걷는다. DRAM PT의 page walk 지연 이득은 측정하지 못했다.
CXL 파일도 L0 DRAM이므로 실제 CXL 지연이 없다. 위 수치는 정확성과 복사·fault·hand-off 동작 비용이다.
사용자 승인 뒤 실제 CXL의 동일 물리 배치를 가진 두 bare-metal host에서 같은 ABAB 조건을 반복한다.
같은 DRAM 데이터를 두고 PT만 CXL/DRAM으로 바꾸는 시험 대조군을 추가해 데이터 지연과 표 지연을 분리한다.
Guest pointer chase, cycle, 지원되는 변환 성능 counter, 첫 fault, pause→명시 ACK, 단계별 시간·부하를 함께 잰다. 자세한 설계는 결과 README 끝에 있다.

## 남은 위험

실제 비일관 장비·다른 물리 서버는 미검증이다. 기존 owner fencing과 mapper epoch 조건에 의존한다.
단일 메모리 영역·같은 root role·읽기 전용 block·NX 큰 page 완화 해제 제약이 남는다.
표 재사용은 release의 이전 owner RCU 종료를 전제로 한다. 실행 중 전환·큰 leaf·자동 정책은 지원하지 않는다.

결과: `docs/results/ept-tier-split-20261119/README.md`, `summary.json`.
원시: `implementation/virtual_machine/.local/run23/`.
다른 세션의 파일과 변경은 보존했다. 메모리 사전 검사 중단 뒤 자기 원시의 page cache만 반환했고 파일은 삭제하지 않았다.
